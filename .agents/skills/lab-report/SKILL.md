Собери итоговый документ лабораторной работы. Учитывай сообщение пользователя,
`AGENTS.md`, `.lab/config.json` и `.lab/gost-formatting.md`.

## Проверка исходников

Если конфигурации нет, нужен `$lab-setup`; если `report.md` отсутствует, нужен `$lab-draft`.
Проверь наличие вывода и дополнительного исследования, если оно запрошено в конфигурации.
Сообщи о пропусках и невставленных результатах. Если данных хватает для запрошенной
сборки, продолжай; не запрашивай подтверждение обычной генерации.
Содержание `report.md` при сборке не меняй.

## Изображения

Просмотри изображения в `images/` доступным инструментом просмотра (`view_image`,
если он доступен). Сопоставляй их с подписями и плейсхолдерами по содержимому,
а не по порядку файлов. Неоднозначные соответствия уточни у пользователя.
Сохрани проверенную карту в `.lab/image_map.json`:

```json
{
  "1": "images/screenshot1.png",
  "2": "images/network_config.jpg"
}
```

Пути отсчитываются от корня проекта. Если подходящих изображений нет, запиши `{}`,
чтобы не использовать старую карту. Несопоставленные плейсхолдеры оставь видимыми
и перечисли их в результате. Не сообщай о вставленных рисунках, если они не попали в документ.

## Сборка

Формат возьми из `preferences.report_format`, имя – из `preferences.output_filename`
(по умолчанию `report`). Учитывай явные пожелания пользователя в текущем сообщении.
Если результирующий файл совпал бы с исходным шаблоном, сохрани результат под именем
`{output_filename}.generated.docx`. Исходный шаблон должен оставаться пригодным
для повторной сборки.

### Markdown

Создай отдельный `{output_filename}.md`; если это `report.md`, используй `output.md`.
Замени плейсхолдеры `[ВСТАВИТЬ РИСУНОК N ЗДЕСЬ]` на Markdown-изображения из карты,
используя соответствующие подписи. Проверь относительные ссылки от итогового файла.
Для этого формата Python и LibreOffice не обязательны.

### DOCX

Проверь окружение: `python3 .lab/scripts/setup_env.py --check` (Windows: `py -3`).
Если оно не готово, подготовь его без `--check`. Используй Python из `.lab/venv`.

```bash
.lab/venv/bin/python .lab/scripts/generate_docx.py \
  --config .lab/config.json \
  --report report.md \
  --output "report.docx" \
  --images images \
  --image-map .lab/image_map.json
```

Замени имя выходного файла выбранным пользователем. На Windows используй
`.lab/venv/Scripts/python.exe`. Если `template.has_template` истинно,
добавь `--template "путь из template.example_path"`; сначала проверь, что файл существует.
Если шаблон был указан, но исчез, сообщи об этом вместо незаметной потери оформления.
Если `preferences.no_title_page` истинно и шаблона нет, добавь `--no-title-page`.

Генератор поддерживает нумерованные и Markdown-заголовки, таблицы, списки,
подписи и изображения. Многострочные блоки кода пропускаются по правилам проекта;
при необходимости иллюстрируй код подготовленными скриншотами.

### PDF

Сначала собери DOCX. Найди `libreoffice` или `soffice` в PATH; на macOS проверь
`/Applications/LibreOffice.app/Contents/MacOS/soffice`. Путь также показывает `setup_env.py --check`.
В Windows типичный путь – `C:/Program Files/LibreOffice/program/soffice.exe`.
Используй найденный исполняемый файл:

```bash
libreoffice --headless --convert-to pdf --outdir . "report.docx"
```

На macOS замени `libreoffice` полным путём в кавычках; в PowerShell перед
исполняемым путём в кавычках поставь `&`. Не меняй формат в конфигурации из-за
отсутствия LibreOffice: сохрани DOCX и сообщи, что для PDF нужно установить
LibreOffice или экспортировать документ вручную. Не объявляй PDF готовым,
пока выходной файл не создан.

## Проверка результата

Проверь, что процесс завершился успешно, итоговый файл существует и открывается.
Для DOCX проверь текст, число встроенных изображений и оставшиеся плейсхолдеры;
при доступном рендеринге также просмотри страницы. Для PDF проверь открытие и страницы.
Проверь, что `report.md` и исходный шаблон сохранились без изменений.
Сообщи путь к результату, число вставленных рисунков и оставшиеся пробелы в данных.
