Настрой проект лабораторной работы в Codex. Прочитай `AGENTS.md`.
Этот навык работает без `.lab/config.json`; существующую конфигурацию используй как основу.
Учитывай сообщение пользователя и уже известные данные, не запрашивай их повторно.

## Окружение

Проверь Python 3.10+: `python3 --version`, на Windows – `py -3 --version` или `python --version`.
Запусти найденным Python `.lab/scripts/setup_env.py`. Скрипт создаёт `.lab/venv`,
устанавливает зависимости и проверяет их. Если окружение уже готово, для проверки достаточно `--check`.
Используй `.lab/venv/bin/python` на macOS/Linux или `.lab/venv/Scripts/python.exe` на Windows.
Проверяй код завершения установки; создание папки venv ещё не означает, что зависимости установлены.
При сетевом ограничении используй штатный запрос разрешения Codex.

Если Python недоступен, продолжи сбор данных и работу с Markdown. Объясни, что
для парсинга PDF/DOCX и сборки DOCX понадобится Python. Не объявляй окружение готовым.
PDF дополнительно требует LibreOffice; для DOCX и MD он не нужен.

## Исходные материалы и шаблон

Найди предоставленные пользователем задание, теорию, пример и шаблон в корне проекта
или по указанным им путям. Возможные форматы: PDF, DOCX, TXT, MD, PNG, JPG.
Сначала отличи задание от пустого шаблона и примера готового отчёта. Если назначение
файла неясно, уточни его; единственный DOCX не обязательно является шаблоном.
Не считай материалами задания `AGENTS.md`, `README.md`, `releases.md`, `LICENSE`,
служебные файлы, `instructions.md`, `report.md` и ранее собранные отчёты.
Если задания нет, попроси положить его в проект или указать путь. Не выдумывай задание.

Разбери шаблон и пример до вопросов о титульном листе. Извлеки из них доступные
данные: вуз, город, предмет, тип и номер работы, тему, студента, группу и преподавателя.
Не меняй исходные документы.

Для полного разбора каждого PDF/DOCX используй:

```bash
.lab/venv/bin/python .lab/scripts/parse_assignment.py --full --images-dir .lab/source-images "путь к документу.pdf"
```

TXT/MD прочитай как текст. Локальные изображения открой доступным инструментом
просмотра (например, `view_image`). Если PDF оказался сканом без извлечённого текста,
используй доступное распознавание или просмотр страниц, либо запроси текстовую версию.
Парсер не выполняет OCR; пустой результат не означает отсутствие задания.

Сохрани полный текст основного документа с теорией и ссылками на изображения
в `.lab/source-material.md`, дополнительные материалы – в `.lab/reference-docs/`.
Извлечённые изображения остаются в `.lab/source-images/`; просмотри их и дополни
ссылки полезными описаниями. Из полного текста выдели задание в `.lab/assignment.md`.
Пути к изображениям, напечатанные парсером, отсчитываются от корня проекта;
при сохранении Markdown в `.lab/` сделай ссылки относительными к этому файлу.

Если есть готовый пример DOCX, можно сохранить его копию в `.lab/templates/example.docx`.
Определи его уровень детализации (`detailed`, `moderate`, `brief`) и особенности стиля.
Если примера нет, используй `detailed` и оформление из `.lab/gost-formatting.md`.

## Недостающие данные

Сначала используй существующую конфигурацию, сообщение пользователя и документы.
Собери оставшиеся данные доступным инструментом вопросов или в чате:

- Студент: ФИО, группа, учебное заведение, город.
- Работа: предмет, тип (по умолчанию «Лабораторная работа»), номер, тема;
  преподаватель необязателен.
- Окружение выполнения лабораторной: ОС и нужное ПО. Оно может отличаться от машины,
  на которой запущен Codex. Особенности сохрани в `system.additional_info`.
- Отчёт: формат (`docx`, `pdf`, `md`), имя файла (по умолчанию `report`),
  стиль (`first_person`, `impersonal`, `result_only`), нужен ли титульный лист,
  дополнительное исследование и пошаговая инструкция.

Не спрашивай о подтверждении неизменённых данных только из-за повторного вызова навыка.
Тип работы определи по заданию: `practical`, `theoretical`, `programming`, `calculation`.
Для практической работы предложи инструкцию; для остальных можно сразу готовить черновик.

## Конфигурация

Создай `.lab/config.json` в UTF-8. Пример структуры (замени значения реальными;
неизвестные необязательные данные оставь `null`):

```json
{
  "student": {"name": "ФИО студента", "group": "Группа"},
  "institution": {"name": "Учебное заведение", "city": "Город"},
  "course": {
    "name": "Предмет", "lab_type": "Лабораторная работа",
    "lab_number": 1, "lab_title": "Тема", "reviewer": null
  },
  "preferences": {
    "report_format": "docx", "output_filename": "report",
    "report_style": "first_person", "no_title_page": false,
    "needs_research": false, "needs_instructions": true
  },
  "system": {
    "os": "ОС выполнения лабораторной", "python_path": "python3",
    "venv_python": ".lab/venv/bin/python", "additional_info": {}
  },
  "example": {
    "has_example": false, "example_path": null,
    "detail_level": "detailed", "style_notes": ""
  },
  "template": {"has_template": false, "example_path": null, "can_edit": true},
  "assignment": {
    "original_file": "task.pdf", "source_material_file": ".lab/source-material.md",
    "source_images_dir": ".lab/source-images", "parsed_file": ".lab/assignment.md",
    "type": "practical"
  }
}
```

Все пути в конфигурации отсчитываются от корня проекта. На Windows запиши настоящий
путь к `.lab/venv/Scripts/python.exe`. При недоступном Python укажи `python_path`
и `venv_python` как `null`. `template.example_path` – путь к пустому шаблону,
а `example.example_path` – к примеру готовой работы; не путай их.

В конце кратко покажи, что настроено, какие материалы разобраны и чего не хватает.
Следующий шаг: `$lab-instructions`, если нужна инструкция, иначе `$lab-draft`.
Не запускай последующие этапы, если пользователь запросил только настройку.
