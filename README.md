# 🧪 LabAI

Ассистент для лабораторных работ в [OpenAI Codex](https://developers.openai.com/codex/).
Помогает разобрать задание, составить план выполнения, оформить полученные результаты
в отчёт и собрать документ с изображениями в DOCX, PDF или Markdown.

Работает как набор навыков внутри проекта. Общение, инструкции и отчёты – на русском языке.

## Требования

- Codex: приложение, CLI или расширение для IDE.
- Python 3.10+ для чтения PDF/DOCX и генерации DOCX.
- LibreOffice, если нужен итоговый PDF.

Python-зависимости устанавливаются в виртуальное окружение `.lab/venv`.
Окружение создаёт навык `$lab-setup` при первой настройке.

## Быстрый старт

**1. Склонируй проект.** Для каждой лабораторной используй отдельную копию,
чтобы задания, результаты и настройки не смешивались.

```bash
git clone https://github.com/id-andyyy/LabAI.git
cd LabAI
```

Папку можно переименовать, например в `Лабораторная 3`.

**2. Добавь материалы в корень проекта.**

| Материал | Пример имени | Для чего нужен |
| --- | --- | --- |
| Задание и теория | `task.pdf`, `task.docx`, `task.md` | Исходные условия лабораторной. |
| Пустой шаблон, если есть | `template.docx` | Титульный лист и оформление преподавателя. |
| Пример готовой работы, если есть | `example.docx` | Образец структуры, стиля и объёма текста. |

Имена могут быть другими. При настройке Codex определит назначение файлов
или уточнит его у тебя. Скриншоты результатов позже складывай в `images/`.

**3. Открой проект в Codex.** В приложении или расширении IDE выбери папку проекта.
Для CLI запусти из этой папки:

```bash
codex
```

**4. Отправь в чате Codex:**

```text
$lab-setup
```

Codex подготовит виртуальное окружение, разберёт материалы, соберёт недостающие
данные о студенте и работе и сохранит настройки в `.lab/config.json`.
Затем предложит перейти к инструкции или черновику отчёта.

Навыки можно вызывать по имени или обычной фразой: «Настрой проект для лабораторной».
В CLI и расширении IDE список навыков открывается через `/skills` или ввод `$`.
Если после обновления проекта навыки не появились, перезапусти Codex в корне проекта.

## Навыки

| Вызов в Codex | Результат |
| --- | --- |
| `$lab-setup` | Подготовить окружение, разобрать задание, пример и шаблон, сохранить конфигурацию. |
| `$lab-instructions` | Создать `instructions.md` с шагами, местами для результатов и указаниями для скриншотов. |
| `$lab-help` | Помочь с конкретной ошибкой или непонятным шагом инструкции. |
| `$lab-update` | Обновить устаревшие шаги инструкции, сохранив уже выполненные. |
| `$lab-draft` | Создать черновик `report.md` по заданию и фактическим результатам. |
| `$lab-improve` | Доработать отчёт по замечаниям. |
| `$lab-research` | Добавить дополнительное исследование или шаги для получения данных. |
| `$lab-conclusion` | Написать итоговый вывод. |
| `$lab-report` | Собрать документ с изображениями в DOCX, PDF или Markdown. |

Пожелания можно писать сразу после имени навыка:

```text
$lab-help команда ping возвращает Request timed out
$lab-improve подробнее объясни результаты проверки DNS
$lab-research сравни TCP и UDP при передаче мультимедиа
$lab-conclusion объём около половины страницы
```

## От задания до отчёта

1. `$lab-setup` – настройка проекта и разбор задания.
2. `$lab-instructions` – инструкция по выполнению.
3. Выполни шаги, заполни результаты в `instructions.md`, положи скриншоты в `images/`.
4. `$lab-draft` – черновик отчёта по результатам.
5. При необходимости вызови `$lab-improve` и `$lab-research`.
6. `$lab-conclusion` – итоговый вывод.
7. `$lab-report` – итоговый документ.

Для расчётной, теоретической или программной работы можно перейти от настройки
сразу к черновику. Если исследование требует новых измерений, Codex добавит шаги
в инструкцию; после выполнения снова вызови `$lab-research`.

Формат, имя файла, стиль текста и необходимость титульного листа задаются при настройке.
Их можно изменить в `.lab/config.json` или указать пожелания при вызове навыка.

При сборке через `$lab-report` черновик `report.md` и исходный шаблон сохраняются.
Если имя результата совпало бы с шаблоном, к нему добавляется `.generated`:
например, `report.generated.docx`. Итоговый Markdown по умолчанию сохраняется в `output.md`.
Для недостающих результатов и изображений остаются заметные плейсхолдеры.

## Виртуальное окружение

Обычно окружение готовит `$lab-setup`. Для ручной подготовки выполни из корня проекта:

**macOS / Linux:**

```bash
python3 .lab/scripts/setup_env.py
python3 .lab/scripts/setup_env.py --check
```

**Windows:**

```powershell
py -3 .lab/scripts/setup_env.py
py -3 .lab/scripts/setup_env.py --check
```

Скрипт создаёт `.lab/venv`, устанавливает туда зависимости, проверяет их совместимость
и сообщает о наличии LibreOffice. Режим `--check` проверяет уже подготовленное окружение.
Для загрузки пакетов нужен доступ к сети; Codex при необходимости запросит разрешение.

После подготовки запускай Python-скрипты через интерпретатор окружения:

| Система | Python проекта |
| --- | --- |
| macOS / Linux | `.lab/venv/bin/python` |
| Windows | `.lab/venv/Scripts/python.exe` |

Для установки дополнительных Python-пакетов используй этот же интерпретатор
с аргументами `-m pip install имя-пакета`.

## Ручной запуск и проверка

Примеры для macOS / Linux, из корня проекта:

```bash
.lab/venv/bin/python .lab/scripts/parse_assignment.py --full --images-dir .lab/source-images "task.pdf"
.lab/venv/bin/python .lab/scripts/generate_docx.py --config .lab/config.json --report report.md --output report.docx --images images --image-map .lab/image_map.json
```

На Windows замени `.lab/venv/bin/python` на `.lab/venv/Scripts/python.exe`.
Для генерации нужны подготовленные `.lab/config.json` и `report.md`.
Чтобы использовать шаблон, добавь `--template "template.docx"` и укажи отдельный
выходной файл через `--output`. Для документа без титульного листа добавь `--no-title-page`.

Парсер извлекает текст и встроенные изображения; для сканов может понадобиться
распознавание текста. Его результат выводится в терминал; файлы с разобранными
материалами сохраняет навык `$lab-setup`.

Карта изображений содержит пути относительно корня проекта, например
`{"1": "images/screenshot1.png"}`. Разбор нескольких документов сохраняет их изображения
под разными именами. Скрипты поддерживают пути с пробелами и кириллицей.

На macOS LibreOffice может отсутствовать в PATH, даже если установлен;
исполняемый файл обычно находится в `/Applications/LibreOffice.app/Contents/MacOS/soffice`.

Проверки парсинга и генерации:

```bash
.lab/venv/bin/python -m unittest discover -s tests -v
```

Структура навыков и вызовы соответствуют [документации Codex](https://learn.chatgpt.com/docs/build-skills).
